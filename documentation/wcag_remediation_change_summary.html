What Changed

The implementation spans detection, handoff, and final PDF structure generation.

1

Detect

OpenDataLoader paragraph blocks are scanned for repeated Likert headers such as Definitely False, Possibly False, Not Sure, Possibly True, and Definitely True.

2

Infer

The detector builds table cell blocks with row, column, header, text, and bounding box metadata.

3

Serialize

The Python remediation service includes table metadata in the temporary layout JSON sent to the C++ remediator.

4

Structure

The C++ builder groups cells by table id and emits /Table, /TR, /TH, and /TD elements with proper parent-child nesting.

5

Verify

The real thesis PDF was regenerated and inspected with pikepdf to confirm table roles and populated data cells.

Before And After

The tester's page 29 issue was a reading-order problem caused by table content being exposed as ordinary paragraphs.

Before

Page 29 was exposed as a stream of paragraph-like blocks. Screen readers had no table structure, no header associations, and no reliable way to connect a response statement to its percentages.

  • No /Table roles on page 29.
  • Table headers were ordinary /P elements.
  • Percentages could be read before the statement they described.

After

Likert tables are represented as nested table structures. Row headers use /TH with row scope, column headers use /TH with column scope, and percentage values use /TD.

  • Page 29 has 2 /Table structures.
  • All 20 page-29 /TD cells contain mapped content.
  • The title, Abstract, and Introduction heading fixes remain intact in fresh output.
